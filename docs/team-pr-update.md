## 账号、退出与素材说明

“记住账号”仅保存邮箱到`autovoyage-remembered-account`，不保存应用密码。读取旧`autovoyage-remembered-login`时迁移邮箱并删除旧含密码记录；浏览器存储被禁用或写入失败时，不阻断已成功的登录。密码输入支持浏览器自己的密码管理功能。

车主“我的服务”的退出按钮先显示确认对话框，确认后才撤销会话；取消或关闭对话框继续使用。车辆图片仍是概念车示意，不表示车主实车或实际品牌配置。Car Concept素材的作者、来源、CC BY 4.0许可及改编说明通过登录页和车主页脚的“车辆素材与许可”访问，详见 [素材说明](image-attribution.md)。

## 手工里程、历史记录与补充项目

“更新里程 → 手工填写”使用实际读取时间与总里程，服务端继续校验车辆归属、未来日期、旧观测、倒退和异常增长。成功后保存明确的手工观测、更新当前里程及时间并重算已有提醒，不生成图片识别结果。

“补录保养记录”允许填写真实历史日期与当时里程。服务端将补录放入车辆启用基准、当前读数、有效观测及既有服务记录构成的时间线：前一节点不能比补录里程更大，后一节点不能更小。同一时刻的里程也须一致。合法历史补录不会降低车辆当前里程或将最新观测时间改早；仅晚于所有已知节点的新增读数才继续接受当前里程质量校验并推进当前车辆数据。

自行补录带“未经门店确认”标记，不生成门店工单或完工凭证。标准项目补录会成为对应已有规则的保养基准，应据实填写；纯自定义项目保留文字，不模糊猜测标准项目、不生成周期，也不重置某项标准提醒。

预约文字补充仅表示额外服务意向，不加入固定报价快照、确定总价或实际完成项目。当前选择器最多补充8项，接口上限12项，每项1–60字、不重复。收费或范围变化仍须走门店提出、车主确认的流程。没有补充项的旧预约请求继续兼容原幂等摘要；有补充项时摘要包含该内容，修改意图需使用新的请求标识。

## 门店成员与首次密码设置

门店管理员只能开通本店的门店管理员或维修专家，所属门店由服务端登录身份确定；平台接口可指定门店，不能通过该入口创建车主或平台管理员。初始密码随机生成、只在本次成功响应显示，数据库仅保存摘要，操作审计不记录密码。

新成员首次登录须校验当前初始密码并设置至少8位、含字母与数字且不同于当前值的新密码。限制在服务端统一执行：完成前只能访问指定身份、配置、健康、退出和改密等接口，业务请求拒绝，初始化数据不返回业务数组。改密后保留当前会话，撤销本人其他会话。

停用成员会立即撤销该账号全部会话，保留业务历史与审计；禁止停用本人、车主或平台管理员，门店管理员不能跨店停用。门店管理员可直接回复本店故障咨询，也可分配专家；车主端保留回复者姓名与身份，初步估价仍不能代替确定报价。

## AI最近结果与常规保养大项

完成的AI查询会向`av_ai_manual_answers`保存当前车型最近一份结构化结果，包含表格、来源、查询时间、保存时间及车型身份。平台管理员可再次查看，新的结果覆盖该车型旧缓存；车型身份改变时提示结果已过时。缓存写入失败不将已经完成的实时查询改成失败。

该表不是正式手册、证据附件、服务项目或已发布规则。用于直接带入的PDF／页图／原文字节仍为按创建管理员隔离的短期内存证据；过期、服务重启或仅打开持久最近结果后，需要重新查询取得有效原文，不能凭最近结果绕过证据校验。明确“带入核对”后才保存手册草稿与证据，人工发布后才生成规则。

V0.9.5的常规主要项目摘要继续适用于其他车型：默认展示主要保养大项，完整细分检查与特殊工况按需展开；带入仍只取常规摘要对应原始行。项目数量由真实手册决定，不固定为9项，不为了凑齐通用目录而生成未知周期，不把完整细目全部默认导入。详见 [常规保养摘要](common-maintenance-summary.md)。

## 手工保养表格

新增“手工录入保养表格”，允许平台管理员按纸质或官方手册录入1–120项。名称可默认生成，版本、HTTPS来源链接及适用说明按实际资料填写；每项保留手册依据摘录、动作、周期类型及真实已知的月份／公里数。系统自动关联能够准确匹配的标准项目，未知关联留空，不自动创建正式项目，也不从项目名称猜测周期。

保存返回`awaiting_confirmation`草稿，标记`entryMode=manual`、`aiModel=手工录入`，没有原件附件，不能描述为AI已读取原件。该模式无需关联系统渲染证据页，但仍保留来源摘录、标准项目、周期、车型身份及规则版本等发布校验。AI／图片入口继续要求真实证据页，不能套用此例外。保存草稿不改变车主计划，核对并发布后才生成本车型规则。

手工表格以当前车型隔离，切换车型会清空未保存内容，页面已提示先保存草稿；保存过程中禁用切换，避免将上一车型表格提交给新车型。已保存的旧AI结果读取不会覆盖本次新查询的状态。人工摘录、图片识别、AI查询最终都进入同一核对发布流程。

以下是本版整合验收点，完成情况由负责人记录到 [验证记录](verification.md)，本清单不作为测试通过声明。

| 模块 | 待核对场景 |

| 登录与退出 | 仅记邮箱、旧含密码缓存清理、禁止存储仍可登录、取消退出保持会话、确认退出失效 |

| 预约项目 | 标准与文字补充展示；总价不增加；重复请求不重复预约；升级前无补充项请求兼容 |
| 门店成员 | 本店开通／停用、跨店拒绝、自停用拒绝、停用会话失效、首次改密前业务接口及初始化数据受限 |
