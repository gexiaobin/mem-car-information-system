# 近年车型年款与配置补充数据

本次补充解决原目录以 2018 年历史数据为主、现代车系及 2024/2025 款缺失的问题。该补充独立于比亚迪官网及公开车型列表数据；加载时需同时合并 `catalog-models-modern.json`、`catalog-variants-modern.json`、`catalog-sources-modern.json`。

## 提取与清理规则

1. CSV 第一行是具体车型 `specid`，后续字段横向按同一列绑定。只从该列读取名称、能源、发动机、电机总功率、变速箱、厂商及乘用级别。
2. 年款必须是完整名称明确写出的 2019—2026 款。配置名称使用 `YYYY款` 后的原文；保留“改款”等真实差异。不给缺失年款补值，不交叉组合年份、动力、配置。
3. 文件名车系必须与每条完整名称中 `YYYY款` 之前的车系严格相符。已发现源站失败回退导致若干商用车文件内容错成小米 SU7 等情况，两个输入共剔除 **201 条错车源行**，防止跨品牌关联。
4. 对“基本型/基本版/高配/中配/低配/概念/试装/待售/预售/未上市”等不能确认实际配置的记录保守剔除，共 **156 条源行**（含两个快照间重复）。没有有效配置的源文件不会创建新车系。
5. 同一 `specid` 优先保留 main，再使用历史归档补缺。比亚迪优先保留专门核对的官网及公开列表：按 `catalog-variants-byd-recent.json` 中 `autohome-byd-spec-*` 的具体 ID 和构建脚本中 34 个已由官网配置替代的精确 ID 排除，两个快照共跳过 406 条源行。不会用近似配置名模糊去重。
6. 系统已有品牌/车系优先绑定原 ID。品牌别名使用明确映射；鸿蒙智行按问界、智界、享界、尊界归属拆分。进口版与国产版不去除括号合并，新车系使用规范品牌/车系 SHA-256 的稳定 ID。
7. 每条输出保存来源 ID、原文件名、具体 `specid` 和完整原名。逐文件原始 CSV SHA-256、统计、排除原因保存在 [vehicle-variants-modern-manifest.json](vehicle-variants-modern-manifest.json)。

## 复现

```powershell
python scripts/build-modern-vehicle-catalog.py
```

使用 Python 3.14+ 即可仅靠标准库读取两个固定版本。较旧 Python 需安装 `zstandard` 以解压历史容器，或加 `--skip-history` 仅生成 main。可传 `--archive <文件>` 使用已下载的 main ZIP；无论本地缓存还是下载内容，脚本均核对固定 SHA-256。历史容器按标准 Base85 → zlib → Zstandard → tar 解码，在内存读取 CSV，从不执行提供者代码、SQL，也不把容器路径提取到文件系统。

构建前应先生成比亚迪补充，以便按精确 `specid` 应用来源优先级。脚本读取主车型目录和 `catalog-models-recent.json`，不读取自身上次生成的 modern 车型目录，因此稳定 ID 和输出可以复现。未纳入的源车系及示例会写入被 Git 忽略的 `.local/modern-research/unmatched.json`，便于后续审核补充。部署仅提供生成后的静态 JSON，不在用户查询或服务器启动时抓取来源站点。
