V0.8.1 补充资料导航：

- [现代车型与历史归档补充](vehicle-variants-modern.md)：PyLab.me 的 CC BY 4.0 数据，按明确的 2019—2026 款及同列事实筛选，补充多品牌近年配置。
- [比亚迪近期年款](vehicle-variants-byd-recent.md)：核对 2024—2026 款公开车型记录与官网参数列，包含用户反馈的海狮06。
- [最新车型配置补充](vehicle-variants-latest.md)：其余近期车型的逐项来源与覆盖边界。
- [公开目录整体来源](public-catalog-sources.md) 与 [选择及导入操作](public-catalog.md)。

基础快照提供 **29,181 条具体配置候选，覆盖 1,655 个车系、173 个品牌名称**，其中 29,169 条是历史结构化数据，12 条是首批人工核对的现代官方配置短事实。**这些数字仅描述基础文件，不是 V0.8.1 合并后目录总量。** 现代补充的固定提交日期、归档标签与查阅日期也不是车型年款；年款只采用来源记录明确的 `YYYY款`。当前总量、实际年款及覆盖范围以目录和各补充说明为准。品牌包含进口、历史及商用品牌，不代表中国当前在售规模，也不表示每个车系或每个年款都有覆盖。

候选保存稳定 ID、车系目录 ID、明确年款、动力描述、原始配置名称、来源 ID、证据摘要和可选厂商。它们供选择后导入正式车型档案，不直接建立保养适用项目、配件规格或保养周期。

## 历史结构化来源：29,169 条

来源：[utf6/Cars_Data](https://github.com/utf6/Cars_Data)，固定提交 [`6ef6168838cf0ec9ebfb9442b4203e7706edbad8`](https://github.com/utf6/Cars_Data/tree/6ef6168838cf0ec9ebfb9442b4203e7706edbad8)。具体输入：[sql/车型表.sql](https://github.com/utf6/Cars_Data/blob/6ef6168838cf0ec9ebfb9442b4203e7706edbad8/sql/%E8%BD%A6%E5%9E%8B%E8%A1%A8.sql)。新来源 ID 为 `utf6-trims-201805`，区别于仅提供车系名称的旧来源。

原 SQL 文件共 87,200,262 字节，212 个字段、32,630 行车型；文件头标注导出日期 **2018-05-06 12:07:04**。仓库提交日期不能作为车型更新时间。所有 SQL 仅作文本解析，未连接 MySQL，未执行其中的 `DROP`、`CREATE`、`INSERT` 或其他语句。

清洗后的历史候选覆盖 1,652 个现有车系、173 个品牌，明确年代款为1999–2019。保留的23条2019款在原始 `年代款` 与 `车型名称` 两字段中都明确写为2019款；这不代表2019年采集，也不把2018导出年份当作车型年款。历史数据不保证当前在售、完整性或与实车一致。

| 处理结果 | 行数 | 规则 |
|---|---:|---|
| 原始车型 | 32,630 | 逐条解析 SQL 单引号字符串、反斜杠转义与 `null`；校验212列 |
| 无法稳定绑定 | 1 | 源品牌必须与车系品牌一致；按品牌与清洗后车系名称精确绑定现有目录，不能仅猜测车系ID |
| 年款冲突 | 64 | `年代款` 必须形如2018款；`车型名称` 的首个明确年款必须一致 |
| 动力缺失或不明确 | 3,389 | 缺燃料形式或有效发动机/电机描述、未知、无单位的“2.0”及明确错字“马坡”等均剔除，不补猜 |
| 非量产候选 | 4 | 配置明确为Concept或试装车；保留实际命名中的smart BoConcept特别版 |
| 展示事实重复 | 3 | 同车系、年款、动力、配置及厂商重复时保留首次源行 |
| 历史候选保留 | **29,169** | 全部可追溯至同一原始车型行，无年款×动力×配置笛卡尔组合 |

动力保存原 `发动机_燃料形式` 与 `基本参数_发动机`；纯电动车只用原 `电动机_电动机总功率(kW)` 的明确数值，并标注单位。原变速箱信息存在时一并保存。没有按排量推断燃料类型，没有将发动机功率与电机功率相加为系统功率。

配置名称取 `车型名称` 中明确“YYYY款”之后的原文字，去除前面的品牌、车系及年款；`manufacturer` 保留源厂商，便于区分进口或合资信息。源内简写、早期命名和事实错误仍可能存在，实车确认与手册审核仍是必要步骤。没有导入原价格、图片、Logo、销售状态、颜色描述或整张参数表。

历史候选的稳定 ID 为 `utf6-model-原车型ID`。车系绑定按品牌+车系名的 NFKC、忽略空白和大小写后精确匹配现有目录；因此已被官网候选替代的车系使用当前目录 ID。没有新增或重写车系目录。

车型表.sql  4207ba72d832f8ce2fe446e0a90f0c91ed6be26b8a55fee173dd927513801ad3

## 复现与维护

在项目目录运行：

```sh
node scripts/build-vehicle-variant-catalog.mjs
```

脚本从固定提交取得三个输入文件，缓存于被Git忽略的 `.local/variant-research`，校验SHA-256后仅解析字符串，并与现有车系目录绑定。12条现代事实明确写在脚本中，更新前须重新人工核对官方表头、版本列和同列参数；它们不依赖运行时向第三方网站发请求。

输出只覆盖 `catalog-variants.json`，本地统计保存在 `.local/variant-research/stats.json`。源码数量或绑定结果变化时脚本拒绝静默替换，须先审阅来源与清洗统计。来源变化同时更新来源记录、本文档及目录版本；不要在自动构建或部署中抓取不稳定官网事实。

基础快照一致性核验：29,181个ID唯一，全部车系与来源引用存在；年款为整数；动力、配置和证据非空；组合后的“动力 · 配置”均不超过正式车型字段200字符；历史记录没有跨原行组合，首批官方记录没有跨配置列组合。现代与近期补充的输入、去重及核验见顶部各自来源说明；合并目录还需检查所有 ID、来源与车系引用。配置目录没有附带保养周期或自动适用项目。
