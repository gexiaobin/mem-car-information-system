## 批次三 · 门店 #1 团队成员新增 / 停用

新增文件：`apps/api/src/members.ts`（182 行，`app.ts` 中与其余 `registerXxx` 一同注册）。

| 路由 | 位置 | 要点 |
|---|---|---|
| `POST /api/v1/admin/store-members` | `members.ts:40` | body `{name,email,role:'store_admin'\|'expert',storeId?}`；`store_admin` 固定本店、`platform_admin` 必须指定 `storeId`（否则 400 `STORE_REQUIRED`）；邮箱重复→409 `DUPLICATE_EMAIL`；12 位一次性初始密码（`randomBytes`，去掉易混字符），账号 `active:true, mustChangePassword:true`；响应一次性返回明文密码，审计明细只记姓名 |
| `POST /api/v1/admin/store-members/:id/deactivate` | `members.ts:85` | 仅同店（平台可跨店）；只能停用门店成员，不能停用车主；操作自己→409 `CANNOT_REMOVE_SELF`；复用注销逻辑 `active:false` + `DELETE FROM av_sessions`，历史与审计保留 |
| `POST /api/v1/auth/change-password` | `members.ts:133` | 校验旧密码（失败 403 `INVALID_CREDENTIALS`）、新密码策略（≥8 位且含字母与数字）、与旧密码相同→400 `SAME_PASSWORD`；成功后清 `mustChangePassword`，保留当前会话、删除其余会话 |

三条路由均挂独立限流。`User` 增加 `mustChangePassword?`，`publicUser()` 透出，登录与 bootstrap 自动带上（`apps/api/src/context.ts:18-25`）。

前端：

- **首次登录强制改密**：`apps/web/src/App.tsx:240` 新增 `PasswordSetup`，在应用外壳处拦截（`App.tsx:99`，位于 `if (!data) return <Login/>` 之后），改密成功才进入车主 `Shell` 或门店/平台工作台。
  **口径说明**：拦截点没有放在登录页——放登录页时刷新页面会走 `/auth/me` 直接进外壳，强制改密可被绕过。
- **成员管理**：`apps/web/src/admin/AdminApp.tsx:152` 成员表新增「操作」列（本人显示"当前登录账号"，其余显示「停用」），表头区新增「新增成员」按钮；`:218` 创建逻辑、`:254` 两个新弹窗（开通成员 / 停用确认）；开通成功后顶部横幅一次性展示初始密码。
- **停用后的兜底**：bootstrap 只下发 `active` 用户，停用成员自动从列表消失；工单/故障处按 id 解析不到时显示「已停用成员」，不再误显示"待分配"。
- 说明文案改为：成员由本店管理员开通，仅能访问本店业务；停用后立即退出登录，历史记录保留。

## 批次五 · 后台 #1 AI 手册持久化 + FR-01① 手册手工录入

### 1. AI 查询结果按车型持久化

- `apps/api/src/db.ts:6-29` `tables` 追加 `"ai_manual_answers"`（启动时 `CREATE TABLE IF NOT EXISTS` 幂等建表）。
- 任务成功回调处持久化：`apps/api/src/manual-answer.ts:335` `persistAnswer()`，在主键 `manual-answer:<modelId>`（`:67 savedAnswerId`）上覆盖写 `{id,modelId,modelIdentity,userId,searchedAt,savedAt,result}`；`result` 保留保养表格 rows、来源、summary、warnings，剔除当次会话才有效的 `mappingDiagnostics`，证据文件不落盘。持久化失败只吞异常，不影响本次查询结果可用性。
  **口径细化**：未建 `(data->>'modelId')` 普通索引——"每车型一行 + 主键覆盖写"使取最新退化为一次主键查询，记录也不会随查询次数无限增长。
- 新路由 `GET /api/v1/admin/manual-imports/ai-answer-saved?modelId=`（`manual-answer.ts:400`，platform_admin）：无记录返回 `{answer:null}`；`modelIdentity` 与当前车型不一致时标记 `stale:true`。
- 前端：`apps/web/src/admin/ManualWorkbench.tsx:123-138`，切换车型的 effect 先查已存结果，命中即以只读态展示（复用现有 `answerExpired` 分支：文案"已整理的结果仍可阅读…"、按钮为「重新查询并整理」）；`stale` 时额外提示"车型资料已变更…请重新查询后再带入核对"；发起新查询时清空该标记。
- 折衷（验收说明）：持久化结果仅供查看，「带入核对」仍需原文证据文件，因此对已存结果引导重新查询。

### 2. FR-01① 平台端手工录入保养手册表格

- shared `ManualImport` 增加 `entryMode?:'ai'|'images'|'manual'`。
- 新路由 `POST /api/v1/admin/manual-imports/manual-entry`（`apps/api/src/manuals.ts:347`，platform_admin，挂限流）：来源元数据（标题可空→按车型自动命名、URL 可空、版本、适用范围）+ `rows`（1~120）+ `consent`；生成草稿 `files:[]`、`aiModel:"手工录入"`、`entryMode:"manual"`、`status:"awaiting_confirmation"`，并带一条"未附手册原件，发布前请逐项核对"的 warning；发布/版本替代逻辑完全复用。
- 校验分支：`verifyEvidence(..., manual)`（`manuals.ts:70`）与 `publicationIssues` 对 manual 跳过页码相关校验，但**每行仍必须有 `sourceText` 依据摘录**；手工草稿发布时跳过"必须存在手册原件"（`SOURCE_REQUIRED`）检查。缺依据的行会在核对阶段以 422 `MANUAL_REVIEW_REQUIRED`（field=`sourceText`）拦下。手工录入不允许把 `sourceUrl` 填成本地文件链接（`SOURCE_FILE_MISMATCH`）。
