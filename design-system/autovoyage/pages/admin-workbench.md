# 云程 AutoVoyage · 管理工作台

设计草案 V0.1；适用门店／专家与平台管理 Web，具体实现与验收另行开展。
全局视觉与交互遵循 [MASTER.md](../MASTER.md)，本文只补充页面规则。

## 角色与信息架构

- 门店管理员：本店待办、预约工单、故障分配、服务价格、时段容量、人员与服务记录。
- 专家／维修人员：本人被分配的本店故障与工单、建议估价、实际服务记录；默认无发布价目表入口。
- 平台管理员：车型与手册规则、标准项目、门店审核、异常与必要日志；不提供随意代改门店价入口。
- 顶部明确当前账号、角色和本店范围；导航按权限呈现，服务端仍独立校验权限与数据归属。
- 门店与平台信息分开展示，避免用角色切换控件暗示普通用户可自行获得管理权限。

## 工作台与详情

- 首屏按可处理事项展示待接单、待回复、待确认变更、待核对完工等队列；统计须有真实数据与口径。
- 表格提供状态、日期、车辆／单号筛选；行操作跟随角色与业务状态。
- 点击待办打开详情页或抽屉，显示车辆、原报价快照、时间线、当前状态、允许操作与必要原因。
- 专家建议区分诊断服务、维修预估、不确定因素和需补充资料；回复不代表故障已排除。
- 完工记录逐项填写实际项目、日期、里程与费用；提交后等待车主确认，异议保留待确认状态。

## 发布与变更确认

- 价格编辑采用草稿 → 校验 → 预览 → 发布；展示车型、材料、范围、费用明细与有效日期。
- 发布前显示字段错误、重叠日期、金额不一致等原因，错误可定位且草稿不丢失。
- 替换价格版本时展示差异、开始生效日期及历史保留说明；已有预约快照保持可追溯。
- 服务增项、材料替换或费用变化单独建变更，展示原方案、原因、差额及车主确认状态。
- 未经车主确认的变更不显示为已认可费用；不提供直接覆盖历史报价的操作。
- 接单、拒绝、取消、关闭时段和完工等操作检查当前状态；破坏性或影响已有预约的操作需明确确认。
- 时段显示容量与已占用数；待确认预约也占名额，容量不得低于已占用数。
- 发布、关键状态变更和确认留有操作者、时间与结果，时间按项目业务时区展示。

## 视觉与响应

- 桌面使用侧栏、筛选栏和高可读表格；详情以清晰分组组织，不堆叠装饰卡片。
- 使用 `--color-background`、`--color-surface`、`--color-border` 建立层级；主操作使用 `--color-primary`。
- 正文与辅助信息使用 `--color-text`、`--color-text-muted`；状态同时呈现文字与语义 token。
- 手机优先保留接单、回复、查看报价和记录服务；侧栏折叠，表格转关键字段卡片，详情可全屏。
- 高密度价格维护在窄屏分步展示；操作栏避开安全区与键盘，焦点和错误提示可见。

## 评审关注

- 各角色只看到可处理的本店／本人事项，平台操作边界清楚。
- 价格发布、费用变更和完工确认均能追溯原信息、确认人和状态。
- 演示统计与工单须标注数据性质；页面草案不代表权限或业务流程已经实现。
