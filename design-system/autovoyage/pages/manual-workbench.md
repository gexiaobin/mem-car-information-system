# 云程 · 按车型导入保养资料

沿用 [全局设计](../MASTER.md) 的海洋蓝、中文字体、表面与语义色。本页针对保养资料导入任务，减少重复操作，不改变原件和规则的来源追溯。

## 工作区

- 车型为全页上下文：先选车型，再查看该车型规则、历史和导入结果。规则默认只显示该车型，切换车型时同步更新；从车型卡片进入时保持其车型。
- 仅提供“AI 查找手册”和“图片识别”两个主要入口。图片支持选择、拖入和粘贴；AI 查询覆盖公开互联网的车系通用手册、保养周期表，具体年款动力作为检索与核对参考。
- AI 查询直接给出已读取的具体手册与保养项目表。结果按“手册原文 → 原文适用范围 → 保养项目／周期／原文依据 → 带入核对”阅读，不再以目录网站卡片替代答案。
- 手册查询使用异步任务，显示服务端真实的“检索手册 → 读取原文 → 整理保养表”阶段；不使用计时器伪造百分比。查询失败、读取进度失败、未取得可整理的保养项目分别明确提示，并保留重新查询与图片入口。
- 只有实际取得的具体资料才显示“阅读手册原文”，官方标识依据返回的来源类别。未读取的目录、网盘入口不作为手册答案或导入按钮；不把搜索结果标题当作已核实适用结论。
- 保养表默认显示项目／动作、首次、后续周期或触发条件；原文摘录、脚注和对应来源按行展开。未注明的周期显示“原文未单列”，不补造周期。资料适用范围独立标注，查询警告在导入前显示。
- 条件项目同时显示原文给出的月份／里程阈值，并注明仅限原文条件，不代表所有车辆的通用到期周期。来源为多份资料时，行详情显示证据编号，不将所有行一律指向主手册。
- 原文适用范围保持可见；较长的来源获取说明和查询待核对事项默认折叠，以数量提示，避免把保养表推离主要阅读位置。结果主按钮为“带入核对 N 项”，下一步核对后才确认发布。
- 查询结果通过服务端留存答案直接带入待核对草稿，避免再次下载和识别。切换车型或离开工作区后旧查询结果不得污染新车型；带入核对不会直接发布规则。
- 答案过期或车型资料变化时保留已显示的内容，主操作改为“重新查询并整理”；网络失败保留结果以便重试。重复带入返回同一份资料，并提示可继续查看，防止重复生成草稿。
- 名称、版次、来源及适用说明由资料自动整理，用户无需上传前填表。可选信息缺失显示“原文未注明”，不逼迫人为编造；高级资料编辑收在详情中。

## 核对与提交

- 默认显示项目、动作、首次与后续周期的紧凑摘要；原文、页图及详细编辑按需展开。
- 依据与动作明确的标准项目自动关联；未知映射留空，不将检查转换为更换。原文没有首保而明确周期时保留首保为空，按周期计算，不让用户重复抄写。
- “确认并导入”一次提交当前编辑和发布，按钮旁清楚说明该操作代表核对原文和车型适用性；不再要求先保存及多个确认框。保存草稿仍是次级操作。
- 失败一次返回全部问题；可聚焦的问题汇总提供对应行入口，展开后有具体字段提示。未选行不作为发布项；排除待处理项必须由用户明确操作，不能静默丢弃。
- 提交处理中禁用重复操作、保留输入，版本冲突不覆盖他人编辑；失败不能生成部分规则，成功显示实际导入数量。

## 可读性与验收

- 主要操作区保持一个主按钮，控制层级与说明数量；控件有可见标签、44px触控区域及键盘焦点。
- 手机车型选择、入口卡和行编辑纵向排布；AI 项目表在手机变为项目卡片，周期左右分列，原文详情保持完整，不产生水平页面滚动。
- 检查车型切换、深链、空车型规则、真实查询阶段、无内容查询、来源链接、项目表、带入缓存草稿、识别加载与失败、集中错误、编辑后一次发布和重复提交。合成验收不写正式业务资料。

UX依据为UI/UX Pro Max的 No Results、Progress Indicators、Focusable Error Summary、Inline Validation、Error Placement，以及React表单submit处理建议；通用配色和布局沿用既有设计。
